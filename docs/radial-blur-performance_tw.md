# 徑向模糊採樣器最佳化

平鋪過濾器在每次操作時準備一次旋轉或縮放比例，並且
在輸出圖塊中重複使用它們。雙線性抽頭將所有色版加載在一起，
一到五個色版的專用循環和通用回退。人造絲
繼續在本機構建上並行化輸出圖塊。

Draft、Good 和 Best 保持上游 64、256 和 4096 間隔上限，範例
位置、透明邊緣和 alpha 算術。正阿爾法
保留取消預乘/預乘序列以保留浮點舍入。
測試與大半徑跨距下未改變的上游採樣器進行比較
灰色、RGB、CMYK 和 Lab，有或沒有 Alpha，深度為 U8、U16 和 F32。
也涵蓋了選擇混合和不尋常的浮動 alpha。

僅準備輸出區域內可達的間隔計數；小貝斯特
影像避免分配/準備完整的大約 64 MiB 轉換表。
準備和輸出分配使用檢查的大小和錯誤的保留。
如果可選最佳化無法準備其表，則現有採樣器
改為執行。在準備期間和輸出圖塊內檢查取消。

此修訂版沒有添加來源大小拒絕：它保留了上游的共享
標準化源讀取，因此仍然需要與源成比例的記憶體
尺寸。它不要求有限的來源記憶體或無限的物理容量。
極坐標近似和背景預覽調度程序是單獨的工作。

|放大| 19.19 秒 | 5.35 秒 | 3.59× |精確匹配|


基線：主`578bc905`處的目前上游採樣器，透過`kernel`，使用
相同的共享來源讀取、256px 輸出圖塊、256 MiB 結果批次、表面
寫回和修剪作為平鋪過濾器。最佳化：`apply_in`。
基準測試的基線包裝器覆蓋全畫布，僅未選擇的過濾；
選擇行為在測試中單獨檢查。

機器：Intel Core i7-9750H（6 核心/12 個邏輯工作執行緒）、Linux、Rust 1.98.1、
具有 opt-level 3、精簡 LTO 和一個程式碼生成單元的發布設定檔。來源：確定性
透明像素的紋理 RGBA8，6000×4000 (24 MP)。品質好，數量1，
中心（0.5，0.5），12 名人造絲工人。每個方法一對執行，上游優先，
經過一次小小的不定時的暖身之後。整個過濾呼叫都是計時的；夾俱生成
每個輸出圖塊的精確比較都在計時器之外。

這些是單一本地測量，而不是跨機器基線或
金額為 100 的績效索賠。較低的金額保持了本次審查的基準
限制在本地筆記型電腦上。品質上限單獨進行大規模驗證
半徑。此範例預設為 3 次交替順序執行，金額為 100
更長的測量。歷史切換極性/預設時序未描述
這種保留輸出的實作。

```sh
cargo run --release -j 12 -p photocraft-algo --example bench_radial -- 6000 4000 1 1
```
