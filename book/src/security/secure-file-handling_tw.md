# 安全文件處理

PhotoCraft在桌面應用程式、CLI、無頭 RPC 伺服器和 MCP 伺服器中讀取和寫入文件。
遠端自動化路徑是在明確授予的根下解析的不受信任的相對名稱。

＃＃ 實施的

- 格式載入器傳回 I/O 和格式錯誤的資料的結構化錯誤。
-`.pcraft`ZIP 載入驗證存檔偏移、條目大小、CRC、內容雜湊和設定的解壓縮大小預算。
- 點陣和 PSD 載入器在主要像素分配之前套用解析器/解碼限制。
- 本機`.pcraft`在相關儲存路徑中儲存使用暫存檔案/重新命名模式。
-`AuthorizedWorkspace`具備遠端獨立讀寫目錄能力
  自動化。
- 絕對路徑、父遍歷、備用分隔符號、磁碟機/裝置/串流前綴、保留
  Windows 裝置名稱、空或點元件以及連結轉義在檔案之前被拒絕
  影響。
- 當其父檔案已存在於寫入下方時，支援不存在的輸出檔案
  根。自動化不會建立呼叫者選擇的目錄樹。
- 未遷移到功能 I/O 的檔案系統承載引擎指令失敗關閉
  自動化。受信任的本機 CLI 子命令和使用者驅動的桌面檔案選擇器保留其
  預期的環境權威。

## 已知限制

- 目錄`.pcraft`捆綁包尚未被記錄為能夠抵抗連結替換或檢查時間/使用時間競爭。
- 根授權是處理程序啟動設定，而不是每個文件的授權。
- 未實現通用方法功能和結構化檔案系統審計事件。
- 授權根內現有的硬連結是受信任的根內容；路徑策略不能
  推斷它們是如何被創造的。

## 基於能力的設計

優先選擇開啟的目錄功能或工作區句柄而不是重複的字串清理：

```text
AuthorizedWorkspace
  - open_document(relative_path)
  - save_document(relative_path)
  - export_render(relative_path)
```

此句柄是根據顯式啟動時授予創建的，保留單獨的讀/寫
權限，拒絕絕對路徑和轉義路徑，並執行相對於所持有的操作
目錄能力。新文件需要現有的根內父文件，因為目標不存在
無法安全地規範化。

## 設計要求

- 僅規範化是不夠的：連結在驗證後可能會發生變化。
- 策略應在平台 API 允許的情況下對句柄和相關元件進行操作。
- 讀取和寫入應該具有不同的功能。
- 替換、新建、截斷和目錄建立語意必須明確。
- 日誌應避免文件內容，並應盡量減少完整私有路徑的外洩。
- 測試應涵蓋`..`、絕對路徑、混合分隔符號、大小寫行為、符號連結/連接、不存在的目標以及受支援平台上的替換競爭。

作業系統帳戶、虛擬機器、容器或沙箱隔離仍然是適當的深度防禦
不受信任的自動化以及通用方法功能尚未涵蓋的控制。
