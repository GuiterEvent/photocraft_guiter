# 控制協議

桌面控制協定是透過綁定到`127.0.0.1`的 TCP 偵聽器的換行符號分隔的 JSON。每個連接上的第一幀必須是帶有設定的 256 位元承載令牌的`auth`。認證後，每個請求攜帶`id`、`method`、可選的`params`；每個回應都包含匹配的`id`以及結果或錯誤。

```json
{"id":"auth","method":"auth","params":{"token":"<64-hex>"}}
{"id":1,"method":"ui.inspect","params":{}}
```

目前的方法目錄包括引擎執行和發現、應用程式開啟/儲存操作、UI 檢查和輸入、螢幕截圖以及文件/控制項幫助程式。權威方法和參數表維護在[`docs/control-protocol.md`](https://github.com/storytold/photocraft/blob/main/docs/control-protocol.md)中。

實施分為：

-`apps/photocraft/src/control_server.rs`：環回 TCP 傳輸；
-`crates/ui-egui/src/control.rs`：即時應用程式處理程序；
-`crates/automation/src/bridge.rs`：MCP 到 GUI 用戶端。

## 目前的安全狀況

**實作：**桌面伺服器綁定IPv4環回；每個 TCP 連線都經過驗證
發貨前；網橋僅接受環回式地址並在其上進行身份驗證
連線；編碼請求行限制為 1 MiB；活動連線數限制為 16 個；
套接字 I/O 和處理程序等待使用逾時； MCP 和無頭批次限制為 256 個步驟。
JSON 行回復和編碼的 MCP 工具結果上限為 8 MiB，並具有聚合批量回复
預算。無頭預覽具有來源像素、請求邊緣和編碼 PNG 上限。的
橋接限制傳入的回复幀和螢幕截圖解碼。
自動化檔案方法需要單獨設定讀取和寫入根。請求路徑是
相對、絕對、遍歷、備用分隔符號、設備名稱和連結轉義路徑是
在文件生效之前被拒絕。

**已知限制：** 令牌是不記名憑證，並授予完整的非檔案系統
控制面。沒有加密、用戶端身分、常規每個方法的能力檢查，
明確 JSON 深度策略、聚合會話記憶體記帳或指令持續時間/取消
預算。桌面擷取/編碼和匯入/匯出仍然需要自己的營運預算。
偵聽器為每個經過身份驗證的執行緒建立一個執行緒
活動連接，位於連接帽內。值得信賴的一次性 CLI 操作和互動式
桌面檔案選擇器保留啟動使用者的正常檔案系統權限。

使用私有令牌文件，僅為受信任的本機自動化工作階段啟用`--control`，且絕不代理環回以外的未加密協定。有關網關的其餘工作，請參閱[自動化安全](../security/automation-security.md)。
