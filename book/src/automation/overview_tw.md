# 自動化概述

PhotoCraft自動化有三種入口樣式：

1.`photocraft-cli`執行有限的轉換、檢查、指令、批次和 Droplet 作業。
2.`photocraft-cliserve`透過 stdio 或環回 TCP 上的 JSON 行保持無頭會話處於活動狀態。
3.`photocraft-climcp`透過 stdio 公開 MCP 工具，無論是針對處理程序內無頭會話或是透過桌面控制伺服器的橋接。

桌面應用程式可以使用`photocraft--control <port>`啟動經過驗證的環回 JSON 控制伺服器。它公開引擎和 UI 操作，包括指標/類型輸入和螢幕截圖。在分派任何操作之前，每個 TCP 連線必須提供設定的承載令牌。

所有編輯路徑最終都會到達命令註冊表。然而，傳輸行為並不等效：只有活動橋可以使用特定於 UI 的方法，且檔案操作在擁有所選後端的處理程序中執行。

## 安全操作假設

- 當不需要 TCP 偵聽器時，首選一次性 CLI 命令或 stdio MCP。
- 使用最低權限的作業系統帳戶執行自動化。
- 請勿持續啟用桌面控制連接埠。
- 不要在命令參數、檔案名稱、文件元資料或日誌中傳送機密。
- 將工具描述和文件內容視為不可信；他們不授予權力。

[自動化安全模型](security-model.md) 中總結了目前的安全限制。
