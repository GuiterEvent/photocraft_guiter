# 選擇距離變換

“選擇”>“修改”>“擴展、收縮和邊框”使用的距離變換現在執行
作為兩個本地並行傳遞。它還為呼叫者提供遮罩和遮罩羽化服務
發動機。合成器有一個單獨的實現，並且不在此更改之外。

第一遍找出每個像素上方和下方最近的選取像素。由於其
輸入是二進位的，兩次掃描取代了該軸的一般拋物線包絡線。垂直
距離按列順序儲存為整數。第二遍複製 32 行帶
分成連續的行併計算平方距離拋物線的下包絡線。
兩個色版的像素數都是線性的。WebAssembly使用相同的標量內核。

行信封遵循 [Felzenszwalb 和 Huttenlocher, 2012](https://toc.cs.uchicago.edu/articles/v008a019/)。
它的交叉點在 f64 中使用`(fq - fp) / (2 * (q - p)) + (q + p) / 2`。這樣就避免老
f32 座標方塊的減法，這在大尺寸上損失了半像素邊界精度
畫布。僅在輸出處距離四捨五入為 f32。

## 正確性

先前的變換可以在選定像素過去的座標處返回正距離
4096. 6000 x 1 完全選擇的光罩再現它。迴歸測試也比較稀疏，
65537 x 2 和 2 x 65537 掩模中的競爭站點與直接歐幾里德距離。

測試針對暴力預言枚舉每個掩碼最多 4 x 3，檢查矩形和
與先前的實作相比，部分行帶保留小數 Expand/Contract/
較小投入的邊界涵蓋範圍，並比較本地工人計數 1、2 和 4。空或
尺寸不一致會傳回空緩衝區。無種子遮罩保留有限的 1e10 結果。
空的和完全選擇的遮罩會跳過變換過程。

大型基準輸入檢查每個選定的像素是否具有零距離並檢查獨立性
角落和中心的最近站點距離。稀疏網格案例與舊案例相符
準確輸出。橢圓和密集情況有意糾正舊的距離錯誤，所以這
並不是聲稱到處都有相同的輸出或測量的Photoshop奇偶性。

## 測量

記錄於 2026 年 10 月 10 日，在 ap-southeast-2 中的 AWS c7i.4xlarge 上：16 個 vCPU、32 GiB RAM、
Rust 1.99.0，工作區的正常發布設定文件，16 個 Rayon 工作人員。合成口罩是
橢圓、稀疏規則網格和確定性密集圖案。輸入生成，
參考驗證和輸出破壞發生在定時間隔之外。
每個實施都會進行一次預熱，然後按交替順序進行三次測量執行。

## 記憶體和限制

舊的變換使用一個 f32 平面。新的變換需要一個 u32 平面加上 f32
結果，或每個像素八個位元組，不包括呼叫者的輸入遮罩。它還使用了多達
每個活動行任務`32 * width * 4 + width * (size_of::<usize>() + 8)`暫存位元組。
在 24 MP 時，兩架飛機總計 192 MB； 36 MP 時，總計 288 MB。完全空和完全
選定的遮罩只需要結果平面。低於 65536 像素的小型混合遮罩串列執行。

額外的平面購買連續的寫入和獨立的並行帶。這仍然是一個密集的
變換，因此它不能解決非常大的 PSB 文件上的流選擇問題。尺寸
在分配之前檢查乘法、元素大小限制和輸入長度。
