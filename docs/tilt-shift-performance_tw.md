## 數位和記憶體契約

Tilt-Shift 有一個頻段，描述為`centerX`、`centerY`、`angle`、`focus`，
`transition`和`blur`；它的引擎/型號沒有引腳參數。六個非零
高斯級加上零級保留其現有的幾何間距，
三盒半徑、smoothstep 西格瑪場和帽子權重。銳利/模糊和
過渡像素仍然混合其原始等級。像素中心，影像
座標、透明預乘和邊緣策略不變。

最佳化的助手克隆已經交錯的源並將其預乘
具有相同的每像素操作。對於每個高斯級別，它保留
原始頂部/左側，僅修剪右側/底部到輸出加上該等級的
盒子半徑的總和。其人工後緣不會透過以下方式影響輸出
三個有限支撐色版。保持領先優勢可以保護
running-sum 初始化、更新順序和 f64 取消，包括 HDR。
沒有樣本或水平被丟棄。裁剪輸出遏制保留
助手現有的回退到完整視窗。

現有的來源、預乘緩衝區、西格瑪圖、累加器和可重複使用
電平緩衝區保留。全窗容量仍預留一次；人口稠密的
長度和模糊划痕縮小。沒有保留快取、功能調度、
臨界值或規劃成本。來源光環讀取、自動平鋪大小、工人數、
選擇混合、輸出寫回、撤銷/重做和取消服務仍然存在
一樣的。任何變更都不需要本機 CPU 功能或不安全程式碼。

綜合測試發現的一個預先存在的崩潰已修復：NaN 低級
模糊量以前成為 f32::clamp 的無效上限。它現在充當
身份。回歸斷言凍結的啟動實施恐慌和
更正後的內核返回來源。有效的有限參數保留精確的位元。

`tests_tilt_shift_reference.rs`凍結起始標量圖庫/移軸
表達式，使用未更改的高斯助手。差異測試比較
每個有限的 f32 位元（包括帶符號的零），具有匹配的 NaN 分類：
1–6 色版，RGB/Gray/CMYK/Lab 和擴充點陣圖/索引/雙色調/多色版
儲存、U8/U16/F32、阿爾法/無阿爾法、窄帶和軟帶
邊界、平移/旋轉帶、微小/空/單行影像、模糊臨界值、
全焦/全模糊、極端和非有限參數、HDR/負片/高對比
樣本、非有限像素、選擇、透明/重複邊緣和圖塊大小
128 年 16 月 47 日。工作前和進度後取消可以保留來源。
也檢查格式錯誤的內部來源長度和零色版。

## 測量方法

Windows x86_64、Ryzen 7 9700X（8 核心/16 邏輯）、64 GiB 安裝 RAM；
穩定的 Rust 1.99.0 / LLVM 23.1.1。正常工作區發布設定檔：opt-level 3，
Thin LTO，一個程式碼產生單元。八名人造絲工人。建置/測試期間停止
併發 Cargo/rustc/benchmark 的測量和過程檢查
工作。普通系統活動和熱/分配器變化仍然存在。

`bench_tilt_shift`構造具有變化的確定性紋理 RGBA 表面
Alpha 和 HDR F32 值。每個案例之前都有兩次不定時的暖身。正時蓋
完整的`apply_in`：來源/光環讀取、平鋪欄位和水平計算、Rayon、
寫回和修剪。不包括夾具構造和輸出破壞。
它使用未更改的管線，而不是隔離的熱循環。基線可執行文件
在編輯演演算法之前建置並保留在本地`plan/`中。
`blurred`案例透過低階 Rust 將條帶置於影像之外
應用程式介面；這是一個飽和場應力情況，位於引擎對話方塊中心之外
範圍。所有其他情況都使用支援的對話方塊參數。沒有引腳列表
為傾斜移位而發明。模型效能針對 RGB 進行測量；其他型號有
由差分正確性測試覆蓋。

預覽工作負載對現有 24 MP 文件的 1500×1000 過濾模型進行建模
代理（因子 4），模糊 15/80/300 變為 3.75/20/75。位置、角度、焦點
而過渡是相對的且不變的。這次過濾代理後
參數更新。它不包括代理構建、會話/歷史記錄、隊列/結算
延遲、合成、GPU上傳和呈現；它不是實際的 GUI 輸入/框架
延遲。此實作不會改變預覽因子或內核。

```powershell
$env:CARGO_TARGET_DIR = 'target/agent-tilt-shift'
$env:RAYON_NUM_THREADS = '8'
cargo run --release -p photocraft-algo --example bench_tilt_shift -- 6000 4000 5 1
cargo run --release -p photocraft-algo --example bench_tilt_shift -- 6000 6000 5 1
cargo run --release -p photocraft-algo --example bench_tilt_shift -- 1500 1000 7 4
cargo run --release -p photocraft-algo --example bench_tilt_shift -- 128 96 7 1
```

＃＃ 結果

順序：基礎 A、候選、基礎 B，每次實現時完成所有四種尺寸
圓形。全尺寸箱子每輪有五個定時樣本；代理和小案件
有七個。 Base p50 匯集了兩個未改變的輪次（10/14 樣本）；候選人
p50 使用 5/7 樣本。範圍包括每個定時樣本，而不僅僅是最佳執行。
本地原始日誌為`plan/tilt-{baseline,candidate,baseline-repeat}-*.jsonl`。

參數由範例固定：`small`模糊 15，居中，角度 0，
焦點0.1，過渡0.15；`medium`在角度 27 處模糊 80；`large`模糊 300，
角度-71，焦點0.03，過渡0.4。`wide_focus`模糊 80，角度 0，焦點 0.4，
過渡 0.05；`sharp_transition`以 (0.2, 0.8) 為中心，模糊 80，角度 63，
焦點 0.05，過渡 0.01。`focused`使用焦點1；`blurred`使用低電平
外部影像中心（-5，-5）。後兩者使用模糊80。單獨代理模糊是
除以四。 U16/F32 對旋轉的中型外殼進行計時。

所有 9 個 24 MP 病例均具有獨立的觀察範圍。收益對於
集中且飽和的應力場。 36 MP 時飽和磁場範圍
重疊；那裡沒有取得令人信服的成果。預覽時預設模糊 15
代理也有重疊範圍：其 1.05× 合併中位數變化尚無定論。
中型/大型代理案例提升1.20/1.35倍，U16/F32中型代理案例提升
1.54/1.55×。小圖像飽和的情況也沒有定論；剩餘的
小影像情況透過分離範圍提高了 1.25–1.91 倍。

存在有意義的漂移，因此合併的 p50 不一定意味著精確的重複性：
24 MP U8 中等基礎 A/B 中位數為 1909.1/1564.3 ms（候選 1241.4），給出
1.54/1.26× 對抗單輪比賽。 36 MP 大箱的基本 A/B 中位數
是 7234.7/9170.0 ms（候選 6176.2），給出 1.17/1.48×。過程CPU採樣
在重複過程中發現基準測試使用約 7.6 個核心，沒有其他重的核心
CPU消耗者。該報告保留了完整的變化，而不是歸因於它
到一個已證實的原因。

對於一套完整的 24 MP 套件（夾具構造、熱身和所有深度/情況
包括在內），採樣的 Windows`PeakWorkingSet64`的基本大小為 2,162,429,952 位元組
候選者為 2,044,227,584，降低約 5.5% (2.01 → 1.90 GiB)。
這是一個相依性分配器的處理程序高水位測量，而不是每個過濾器
活記憶界。分配計數未偵測；來源副本，
sigma-map、級別元資料、輸出和級別緩衝區分配保留，以及全視窗緩衝區
容量被保留。較小的人口水平和刮擦佔
結構性工作減少。 SIMD 與 FFT 交叉表現皆不理想
聲稱；沒有引入自適應臨界值。

在差分測試中觀察到的最大有限像素誤差**為零**。每個
像素必須匹配，因此不能出現局部帶邊緣、接縫、不透明度或混疊錯誤
隱藏在平均誤差指標中。 NaN 分類匹配。 NaN 模糊崩潰
回歸透過返回身分有意與起始核心不同。
