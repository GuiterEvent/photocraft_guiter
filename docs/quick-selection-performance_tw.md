# 快速選擇筆畫表現

於 2026 年 10 月 10 日在 AWS c7i.4xlarge、Intel Xeon Platinum 8488C 上測量
16 個 vCPU、32 GiB RAM、Ubuntu 24.04、Rust 1.99.0。發布版本和
預設本地工人數量。建置和其他測試在計時期間處於空閒狀態。
演演算法提交：`78dca424510bbdecb01228a4a98a971fd070b658`。

## 發生了什麼變化

所安裝的快速選擇能量、刷子佔地面積、成本、重量、工作
解析度、邊界帶和視窗擴展規則保持不變。

具有兩個終端方向的大型有限圖使用 FIFO 推送/重新標記，
由 [Goldberg 和 Tarjan (JACM 1988)](https://doi.org/10.1145/48014.61051) 實施。
局部多餘的推送取代了重複的增廣路徑。週期性全球
重新標記計算到接收器的距離，並且對於其餘頂點，
回到源頭。傳回未使用的來源流對於保留
可行的殘差圖並支援添加容量後的另一個解決方案。
最終的源可達性傳遞會傳回最小的源端切割。
4096 個節點以下的圖、單端圖以及具有非有限或
負邊緣容量保留現有的 Boykov-Kolmogorov 實作。
兩個解算器都使用現有的 f32 剩餘容量和飽和 epsilon。
新的解算器儲存f32反向來源容量和f64剩餘量，12位元組
每個空閒圖節點，並重複使用圖的高度、目前弧和活動陣列。

圖建構跳過兩個固定像素之間的權重。少於
八分之一的空閒像素，五路合併僅枚舉規範邊緣
與自由像素相關的來源，依其原始點陣順序。這使得
邊緣枚舉和權值評估O(自由像素)，而現有的
索引和終端設定在工作影像中保持線性。儲存
邊順序也保留 f32 累積到固定鄰居終端。

窗口擴展、佔地面積和距離成本、從粗到細的切割、掩模
上採樣和區域修剪。文件建置不在計時器之內。

## 正確性與迴歸檢查

- 1170 個整數容量圖將流量和所有標籤與 BK 進行比較，然後再次求解。
- 600 個任意 f32 容量圖將流量和所有標籤與 BK 進行比較。
- 240 個分數圖列舉了每種可能的切割，檢查最佳能量
  以及獨立於 BK 的所有最優源集的交集。
- 5000個節點的斷鍊檢查回源進度，重複
  解決，並在另一個解決方案之前添加連結。
- 詳盡的小約束掩模和邊緣源掩模覆蓋邊界，
  對角線、退化維度和捆綁切割。
- 36 個完整的快速選擇比較，涵蓋紋理、低對比、漸層、
  噪音、細條、圓盤、均勻區域和畫布邊框筆劃，直接
  以及由粗到細的切割。
- 每個測量的工作流程都會比較完整的區域邊界和遮罩位元組。

## 複製

```sh
cargo test --release -p photocraft-algo quick_selection_surface_release_comparison -- --ignored --nocapture --test-threads=1
cargo test --release -p photocraft-algo quick_selection_workflow_release_comparison -- --ignored --nocapture --test-threads=1
cargo test --release -p photocraft-algo solver_workload_release_comparison -- --ignored --nocapture --test-threads=1
```

私有常數測試路徑保留了先前的密集權重掃描和
未更改的 BK 解算器，共享全行程管線的其餘部分。僅求解器
固定裝置還包括鍊式、單端網格和密集端網格
位於 1024、4096、16384 和 65536 個節點。他們的數字只是衡量解決方案，
在計時器之外進行圖形克隆。
