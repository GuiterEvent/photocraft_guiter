# 安全概述

PhotoCraft處理複雜的攻擊者控制的文件，並公開可以根據使用者的檔案系統權限進行操作的自動化。因此，安全性是解析器、引擎、I/O、自動化、發布和相依性設計的一部分。

## 當前姿勢

|面積 |實施保護 |已知的限制/未來的工作|
|---|---|---|
| PSD/PSB |標頭、色版、解碼位元組、嵌套和模式限制；畸形/效能測試；模糊目標|更廣泛的敵意語料庫、總體工作預算、嵌入對象覆蓋範圍 |
|點陣編解碼器 |預設尺寸/像素/分配限制；特定於解碼器的預算；畸形/效能測試；模糊目標|連續模糊測試和更多格式特定的語義案例 |
|`.pcraft`|清單/blob/總位元組限制；有界減壓； CRC/散列和版本檢查；模糊目標|更嚴格的複雜性/條目限制和目錄包路徑競爭分析 |
|引擎指令|錯誤返回合約、重點不良參數測試、對抗性`panic_hunt`測試 |繼續消除輸入衍生的恐慌和疲憊路徑 |
|控制 TCP | 環回綁定；不記名令牌認證；root 讀/寫權限；1 MiB 請求行；8 MiB 回复；16 個活動連接； I/O 逾時 |沒有通用方法功能、加密、用戶端身份、明確 JSON 深度策略、聚合會話記憶體/命令持續時間預算或審計跟踪 |
| MCP|工作室；打字工具；經過身份驗證和有界的橋； root 讀/寫權限；256 步批次，具有匯總回复預算；無頭預覽/輸出上限|沒有通用工具授權範圍、聚合會話記憶體核算或命令取消；回車回復大寫不綁定桌面截圖|
|相依性關係 | Cargo 鎖定檔案與普通 CI 建置/測試/clippy |目前樹中未確認`cargo-audit`或`cargo-deny`作業/設定 |
|發佈 |設定機密時的校驗和和平台簽章/公證路徑 |可以不簽字；目前樹中沒有確認 SBOM 產生 |

此表是目前儲存庫的快照，不能保證已部署的工件。驗證來源並發布高風險使用證據。

## 安全優先事項

1. 在經過身份驗證的傳輸之上新增功能範圍的自動化會話。
2. 隨著文件承載指令的發展，維護已實現的工作區句柄邊界。
3. 將預覽/回覆預算擴展到 JSON 複雜性、聚合文件/會話記憶體、
   桌面捕獲/導入/導出以及命令持續時間/取消。
4. 使用回歸語料庫擴展 PSD/PSB、編解碼器和`.pcraft`模糊測試。
5. 新增相依性建議/許可證策略檢查並發布 SBOM。

從[威脅模型](threat-model.md) 開始，然後使用重點頁面進行檔案處理、解析器、模糊測試和自動化。
