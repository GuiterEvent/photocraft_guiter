# 釋放安全性

PhotoCraft的發布工作流程從`release`分支建立平台包和 GitHub 版本草案。權威處理程序是[`docs/releasing.md`](https://github.com/storytold/photocraft/blob/main/docs/releasing.md)。

## 實作的工作流程元素

- macOS 和 Windows 存在特定於平台的簽章/公證步驟；
- 簽名機密的範圍透過 GitHub`release`環境；
- 發布工件包括`SHA256SUMS.txt`；
- 最終發布作業接收`contents: write`，而建置作業使用更窄的存取權限；
- 工件保留在草稿版本中，直到維護者發布它們。

簽約是有條件的。當簽名材料不可用時，工作流程可以產生未簽署的工件並發出警告。消費者和維護人員必須驗證工作摘要和工件簽名，而不是假設每個版本都已簽名。

## 未來強化

- 為每個版本產生機器可讀的 SBOM；
- 發布與來源提交和工作流程相關的出處/證明；
- 在發布元資料中明確簽章狀態；
- 在發布之前驗證校驗和、簽名、公證和安裝程序行為；
- 檢視動作固定和釋放工具的來源；
- 記錄密鑰輪換和妥協回應。

建置、簽署、起草、發布和部署是不同的狀態。成功的建置不得報告為已發布的版本。
