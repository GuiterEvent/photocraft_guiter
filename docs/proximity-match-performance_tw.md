# 鄰近匹配搜尋和記憶

Spot Healing 的鄰近匹配透過比較周圍的環來選擇源位移
癒合孔。兩項更改減少了搜尋工作：

- 源有效性計數在孔的非零邊界框上使用求和麵積表。
  此框外的每個排除單元格均為零，因此翻譯和剪切查詢給出
  與全影像表相同。這也覆蓋了分離的孔和畫布邊緣。
- 每 32 個環樣本後，將每個候選者的 SSD 與最佳分數進行比較。全部
  SSD 項是非負的，因此部分總和除以最終樣本數
  乘以相同的距離罰分就是最終得分的下限。候選人
  達到最好成績的人無法贏得現有的嚴格比較。

樣本順序、累積順序、距離懲罰、候選訪問順序、平局處理、
搜尋半徑和來源像素複製保持不變。非有限最佳分數禁用修剪。
裁剪後的表會檢查分配、算術和來源切片，並在失敗時傳回 None 。
內容感知完成和紋理合成使用的其他求和區域表未更改。

## 測量

於 2026 年 10 月 10 日在 AWS c7i.4xlarge、Intel Xeon Platinum 8488C、16 個 vCPU、32 GiB RAM、
Rust 1.99.0，正常工作區發布設定檔。這個內核是串行的。輸入是合成的
週期性RGB浮動紋理和圓孔；值是在計時之前產生的。每條路徑
進行熱身和五次測量跑，交替舊/新順序。每次執行檢查都相同
相對於舊實現的源位移。

這四個小區域遵循現有修飾基準的筆畫域大小：
`width = height = diameter + 2 * (diameter + 16)`, search radius`diameter + 16`.
環寬度為`clamp(diameter / 8, 3, 16)`。 Large-image cases use search radius 512.
這些是內核呼叫，不包括筆刷點陣化、表面讀取、泊松混合、
document history and compositing.

引擎已經對局部區域產生了正常的治療效果。大圖案例
顯示公共核心的擴展，而不是額外的 4.6–6.2 倍 UI 加速。源紋理，
孔形狀、候選有效性和當前最佳匹配的品質影響剪枝；
這些測量並沒有建立最壞情況下的加速或Photoshop影像品質奇偶校驗。
邊界覆蓋影像的洞仍然需要全尺寸的桌子。

## 正確性和再現性

測試將矩形的裁切計數與全表計數進行比較，矩形完全位於內部、外部、
越過或夾住洞的邊界。它們包括分離的孔、帆布邊緣、
非常大的查詢座標和檢查表分配/邊界失敗。

搜尋測試將精確的來源位移與先前的實作進行比較
1、3、4、5 色版； 8位元、16位元和浮點工作值；多個環/搜尋半徑；
空洞、單像素洞和分離洞；均勻聯繫和非有限樣本。一個完全
未知圖像仍然沒有候選來源。

```sh
cargo test --release -p photocraft-algo proximity_integral_release_comparison -- --ignored --nocapture
```

舊的搜尋僅保留在測試模組中。所選源位移為
不變，因此下游來源補丁複製和梯度域混合獲得相同的輸入。
