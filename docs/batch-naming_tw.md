# 批次輸出命名

選擇記錄的操作，然後開啟 **檔案 > 自動 > 批次**。設定輸入和輸出
資料夾。 **檔案命名**接受檔案名稱主幹範本；選定的匯出格式提供
擴展名。將其留空以保留現有的來源檔案名稱和衝突報告。

|代幣|價值|
| --- | --- |
|`{name}`|輸入不含最後副檔名的檔名 |
|`{serial}`|輸入位置加上**起始序列**（預設1），填入至少三位數字|
|`{date}`|批次開始時的 UTC 日期，採用`YYYY-MM-DD`形式 |

例如，以串列 7 開頭的`{name}_{serial}`寫入`photo_007.png`並
`photo_008.png`用於兩個名為`photo.png`的 PNG 輸入。 999之後的連載變成了1000；
它不包裹。資料夾輸入使用現有的檔案名稱順序和明確輸入陣列
保持其秩序。失敗的輸入會佔用它們的位置，因此後面的檔案名稱不會改變。
輸入檔名中的大括號是文字文本，而不是附加標記。

未知標記、不符的大括號、無效參數類型、路徑分隔符號、保留檔名
字元、檔案名長度過長（255 UTF-8 位元組）和序列溢出之前被拒絕
導出寫入開始。起始序列必須是 1 到 4,294,967,295 之間的整數。
解析為現有輸入檔的自訂範本也會被拒絕；選擇一個單獨的
目的地或其他模板。普通的每個文件讀取、操作和保存失敗仍然出現
在批次的`errors`結果中。當兩個結果共享一個名稱（包括僅大小寫差異）時，
保留第一個成功結果並報告後來的碰撞。

透過引擎命令介面，`file.automate.batch`上可以使用相同的選項：

```json
{
  "input": ["first/photo.png", "second/photo.png"],
  "output": "exports",
  "steps": [["image.adjustments.invert", {}]],
  "format": "png",
  "naming": "{name}_{serial}",
  "startingSerial": 7
}
```

CLI 可以使用`run --cmd file.automate.batch --params ...`呼叫此指令。
此選項屬於Batch；影像處理器和液滴選項保留其現有行為。
