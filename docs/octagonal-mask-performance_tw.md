# 精確的八邊形掩模移位

選擇並遮罩將“移動邊緣”應用為平面灰度膨脹或腐蝕。此前，
`matting::morph`對於每個半徑步驟執行一次完整的 3x3 遍，交替使用一個正方形和一個正方形
交叉。 64 像素的偏移需要 64 個影像色版。此過濾器支援部分覆蓋。

## 分解

對於半徑`r`，設`a = ceil(r / 2)`和`b = floor(r / 2)`。原來的足跡是
剛好是半徑為`a`的平方，後跟半徑為`b`的曼哈頓球：

```text
max(abs(dx) - a, 0) + max(abs(dy) - a, 0) <= b
```

等效地，`max(abs(dx), abs(dy)) <= r`和`abs(dx) + abs(dy) <= r + a`。
重新排序單位正方形和十字可保留矩形上的足跡
畫布：任何包含的像素的路徑都可以保留在畫布內部的端點之間。
沒有外部像素參與舊的剪切色版或新結果。

此方塊使用現有的 van Herk / Gil-Werman 前綴/後綴視窗極值，其中
每個樣本的不斷比較。執行至少 262,144 像素的本機密集緩衝區
並行水平窗口，在 32x32 快取區塊中轉置，過濾連續列，然後轉置
回來。兩個全尺寸浮動工作平面被重複使用。小投入和 wasm 保持
串行方形通行證。每個軸都限制該軸範圍內的視窗半徑。

曼哈頓球是由半徑的二進制數字構成的。半徑為`2d`的球是
五個半徑為`d`的滾珠的結合，以輸出為中心，其四個軸向偏移量為
`d`像素。對於較大球中的任意點，選擇其較大的絕對座標。
沿著此軸移動中心`d`像素，曼哈頓距離最多為`d`。
將該中心夾在畫布上會保留此屬性，並且不會增加佔用空間
像素。奇數半徑加倍後會增加一個單位十字。

對於沒有 NaN 或負零的掩碼，這會將工作從 **O(width * height * radius)** 更改為
**O(寬度 * 高度 * log(半徑 + 1))**。大型本地交叉傳遞也並行運作。
小半徑 0-2 保留原始路徑。 NaN 和負零保留原始值
比較順序，包括 NaN 有效負載和有符號零行為。其他值，
包括無窮大和 HDR 遮罩值，使用精確的最大/最小比較，沒有
量化或浮點和。

## 全面的 CPU 最佳化

第二個比較運作實際平舖的`refine_mask`管線，僅交換
前一個循環和新實現之間的形態回調。它包括
引導取樣、引導濾波、邊界距離、量化、圖塊組裝和
輸出微調。兩條路徑都使用相同的合成 RGB 導軌和修剪後的圓形
選擇，半徑 64 和移動邊緣 +100%。每個結果的邊界框和每個掩模
位元組必須匹配。熱身和三輪交替配對跑使用與上述相同的方法。
文件大小為 24 和 36 MP；選取範圍是透過正常工作流程裁切的。

## 有界工作區

對於沒有 NaN 或負零的影像形狀遮罩緩衝區，至少 1,048,576 像素，寬度至少 256，
高度至少為 128，半徑為 3-64，傳回的 f32 輸出是唯一的全影像分配。每個活躍的worker最多使用一個384x256的光環窗口，其中三個f32
平面和小於 6 KiB 的線路划痕。在 16 個工人的情況下，派生的分配界限，
包括輸出在內，與舊版相比，約為 **24 MP 時為 115 MB** 或 **36 MP 時為 163 MB**
**192 MB / 288 MB** 兩平面工作空間。這大約減少了 **40% / 43%**。這些是
分配範圍，未測量處理程序 RSS；來源和呼叫者保留的副本是
分開。對於 N 個像素和 P 個工作執行緒，界限是`4*N + P*(12*384*256 + 6144)`
位元組。恆定的視窗不需要過濾器刮擦。更小的呼叫和更大的半徑使用
密集分解，用兩個f32工作平面加線刮痕。

## 正確性和再現性

覆蓋範圍包括最大 4x3 的小型矩形畫布上的所有二元遮罩；每個半徑
小數 8 位元、16 位元和 HDR 浮點值為 0-65；轉角處的衝動足跡，
邊緣和內部位置；薄圖像；部分轉置塊；工人數量
身份；無限大、NaN 有效負載和有符號零。比較移位平鋪遮罩
跨畫布和圖塊邊緣進行整體緩衝區細化。檢查尺寸拒絕
短輸入和乘法溢出。半徑大於畫布飽和度
分解路徑上可到達的範圍，包括非常薄的畫布。

```sh
cargo test --release -p photocraft-algo octagonal_morphology_release_comparison -- --ignored --nocapture --test-threads=1
cargo test --release -p photocraft-algo tiled_refinement_release_comparison -- --ignored --nocapture --test-threads=1
cargo test --release -p photocraft-algo dense_matte_release_comparison -- --ignored --nocapture --test-threads=1
```

基準測試的舊路徑也是特殊值和的生產回退
小半徑。它使用先前的循環，而無需更改封裝或連接順序。
