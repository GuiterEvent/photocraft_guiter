# 模糊測試和回歸測試

PhotoCraft的主要不受信任格式 crate 旁邊已經有`cargo-fuzz`工作區：

|板條箱 |目標 |
|---|---|
|`crates/psd`|`parse`,`descriptor`|
|`crates/codecs`|`decode_any`,`decode_png`,`decode_jpeg`,`decode_tiff`,`decode_exr`|
|`crates/format`|`load`|

主 CI 工作流程可以透過手動排程的模糊作業來執行這些目標。目前沒有安排連續模糊測試。

從安裝了 nightly Rust 和`cargo-fuzz`的 crate 目錄執行目標：

```sh
cd crates/psd
cargo fuzz run parse
```

普通測試套件透過屬性測試、結構化畸形案例、截斷掃描、位元突變、類似炸彈的標頭、存檔損壞和命令`panic_hunt`覆蓋來補充 libFuzzer。

## 安全性屬性

有用的模糊目標應該檢測的不僅僅是記憶體安全崩潰。相關故障包括：

- 恐慌或中止；
- 整數溢位或越界存取；
——分配不合理或減壓擴容；
- 逾時、無限循環或演演算法複雜性峰值；
- 遞歸/堆疊耗盡；
- 格式錯誤的輸入被接受為無效的內部狀態；
- 偵測和顯式格式解碼之間的結果不一致；
- 儘管散列/CRC 不匹配，但仍接受損壞的`.pcraft`內容。

## 語料庫政策

在揭露和許可允許的情況下，每個已確認的缺陷都應產生最小化的永久回歸測試。僅儲存合成或可重新分配的輸入。請勿提交個人文件、客戶資料、憑證、專有資產或未公開的武器化樣本。

回歸條目應記錄受影響的解析器、預期錯誤類別、資源預算以及揭露後的問題/諮詢參考。在修復被認為是持久的之前，必須在正常測試下重現模糊崩潰。
