# UI 本地化和即時語言切換

PhotoCraft在本機eguishell 和
WebAssembly建置。英文來源字串是查找鍵。 UTF-8 TSV 目錄提供純文字、
上下文、命令 ID 和複數翻譯；缺少的條目將恢復為英文。

## 切換無需重啟

開啟 **編輯 > 首選項 > 介面 > 語言** 並選擇一種語言。偏好
對話方塊以所選語言預覽其標題、控制項和按鈕。 **取消**丟棄
預覽，**應用**提交它而不關閉對話方塊，**確定**提交並關閉。
介面的其餘部分遵循下一次繪製時所承諾的偏好。現有
在語言變更期間，文件、撤銷歷史記錄和工具仍然可用。

現有的偏好儲存保存選擇以供將來啟動。`auto`遵循
本機系統區域設定；不支援的程式碼遵循相同的後備措施。區域標籤，例如
`fr-CA`、`ko-KR`、`vi-VN`和`zh-CN`解析為對應的註冊目錄。傳統和
簡體中文仍然獨特。每個葡萄牙語區域設定（`pt`、`pt-BR`、`pt-PT`）都使用
巴西葡萄牙語目錄。塞爾維亞語目錄以拉丁文字（Ekavian）書寫；每個
塞爾維亞語言環境（`sr-RS`、`sr-Latn-RS`、`sr_RS@latin`和西里爾語`sr-Cyrl-RS`）解析為它。

### 首次啟動與系統語言

如果沒有儲存首選項，`interface.language`預設為`auto`，因此第一個渲染的
視窗使用第一個受支援的系統 UI 語言。沒有這個的舊首選項文件
字段也使用 Auto。如果偵測失敗或沒有註冊任何首選語言，
UI 使用英文 (`en`)。儲存的手動語言選擇優先於以後的啟動；
啟動永遠不會覆蓋它或將偵測到的語言寫入首選項檔案。

僅本機固定的`sys-locale`相依性提供對平台 API 的安全 Rust 存取：

- **Windows：**`GetUserPreferredUILanguages`，依照使用者的首選順序。這使用了用戶介面
  日期和數字的語言而不是區域設定；它們可以不同。
- **macOS：**`CFLocaleCopyPreferredLanguages`，依首選順序，無需啟動`defaults`
  或取決於特定的`.plist`表示。
- **Linux/BSD：** 平台的標準語言環境，包括`LANGUAGE`清單。

`PHOTOCRAFT_LOCALE`是可選的單標籤覆蓋，用於可重複啟動；一個不支援的
override 回落為英文。空覆蓋使用系統。 Unix 區域設定變數不
覆寫 Windows/macOS UI 語言首選項。每個行程讀取一次標籤（最多 64 個，
每個 128 位元組）並與支援的語言註冊表進行匹配。更改為
作業系統語言清單本身在下次啟動時生效。網路建置保持現有狀態
英文 自動回退，直到實現瀏覽器區域設定偵測。

API 實作與授權：[sys-locale](https://github.com/1Password/sys-locale)。

代理程式透過 CLI、MCP 或桌面控制色版使用現有的`prefs.set`指令：

```json
{"method":"engine.execute","params":{"command":"prefs.set","params":{"path":"interface.language","value":"ko"}}}
```

控制請求在同步繪圖語言之前處理，因此請求
更新同一渲染影格中的標籤。繪圖語言是 UI 執行緒本地的；
即使繪圖展開，範圍預覽也會恢復先前的語言。選單和對話方塊
身分繼續使用指令 ID，獨立於翻譯標籤。

這是捆綁目錄之間的熱切換。目錄檔案嵌入
`include_str!`；編輯 TSV 檔案需要重建。外部目錄觀看和
文件資源熱重載未實作。

## 從右到左的語言

阿拉伯語、希伯來語、波斯語、烏爾都語和其他從右到左列出的語言
`i18n::dir_for_code`選擇後會鏡像視窗的鑲邊：選單列從右側開始
使用文件時，工具箱停靠在右側，面板停靠及其導軌位於左側，
標題、選項和狀態列從右側讀取 (`crates/ui-egui/src/direction.rs`)。的
方向遵循語言程式碼，因此目錄不需要額外設定。

尚未鏡像：面板內部、對話方塊、選單列（捷徑保留在右側）、子選單
（它們在右側打開）、文件選項卡和畫布。在阿拉伯文目錄閱讀之前
正確的是，UI 還需要阿拉伯語後備字體（捆綁的 UI 字體沒有阿拉伯語字體）
字形）和雙向詞序：egui0.36 使用 HarfRust 塑造每個從右到左的單詞，
因此字母連接在一起，但將一行的單字從左到右排列，並且其插入符號索引在
從右到左的文字（emilk/egui#8576、#8577）。文件文字由文字引擎佈局。

尚未發布從右到左的目錄。若要檢查任何語言的鏡像佈局，請啟動
`PHOTOCRAFT_UI_DIRECTION=rtl`（或`ltr`強制從左到右）；每個行程讀取一次
且對網路建置沒有影響：

```sh
PHOTOCRAFT_UI_DIRECTION=rtl cargo run -p photocraft-ui-egui --example snapshot -- --out rtl.png
```

## 字體

本機惰性 CJK 字體載入器優先考慮所選的日文、韓文或中文指令碼。
切換語言會重建字體定義並重置現有的載入程序，因此字體
從定義中刪除可以再次註冊。空閒幀保留其字體快取。
其他語言保留系統對文件名稱和文字的 CJK 後備首選項。

字體檔案不會新增到此儲存庫中。本機渲染使用已安裝的系統字體
以及可選的製程字體建置輸入；請參閱[字體](development.md#fonts-craft-fonts)。
Web 建置可以選擇每個目錄，但 CJK 字形交付和自動瀏覽器區域設置
檢測仍然是單獨的懸而未決的工作。切換目錄不會提供缺少的字體。

## 新增或維護目錄

1. 在`crates/ui-egui/src/i18n`下方新增`<code>.tsv`，位於`ja.tsv`中的標題之後。
2. 在`i18n::LANGUAGES`中註冊其程式碼、本機名稱和複數規則。
3. 翻譯英文源鍵的意思。保留`{name}`佔位符，轉義
   字元和對話方塊指令中的尾隨`…`。使用`@id`消除指令歧義
   label 和`@plural`用於計數敏感文字。保留產品名稱，例如PhotoCraft。
4. 當目錄覆蓋所有強制密鑰時，設定`complete_menus`。新增來源和許可證
   翻譯資產的歸屬，然後執行目錄和 shell 測試。

```sh
cargo test -p photocraft-ui-egui --locked
cargo clippy -p photocraft-ui-egui --all-targets --locked -- -D warnings
cargo xtask i18n-coverage
cargo xtask layers
cargo xtask wasm
```

使用離屏`snapshot`範例渲染代表性對話方塊，包括序列
一個過程中的語言變化。檢查 PNG 是否缺少字形和被截斷的標籤。
翻譯是原創作品或重複使用記入PhotoCraft的開放貢獻
[ATTRIBUTION.md](../ATTRIBUTION.md);不使用專有的本地化資源。
