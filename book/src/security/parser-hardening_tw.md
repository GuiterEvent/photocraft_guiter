# 解析器強化

解析器安全性比“不崩潰”更廣泛。解析器還必須限制記憶體、CPU 時間、遞歸、輸出擴展以及它創建的物件數量。

## 實施的控制

### PSD/PSB

`photocraft-psd`強制執行最大文件尺寸和色版計數，限制解碼色版數據，限制 ActionDescriptor 嵌套和模式邊緣，並使用檢查算術進行關鍵解碼大小計算。測試涵蓋格式錯誤的標頭、截斷、屬性產生的輸入和專用模糊目標。

### 點陣編解碼器

`photocraft-codecs`具有可設定的`Limits`的寬度、高度、像素數和解碼分配。預設策略適用於啟用的解碼器，並使用超大的 PNG、PNM、JPEG 和 TIFF 標頭以及隨機/變異輸入進行測試。

### 原生格式

`photocraft-format`限制清單、blob 和總解壓縮位元組數；在為其解碼任何內容之前，承認聲明的畫布（預設情況下每邊最多 300000 像素，最大畫布`file.new`、畫布大小和 PSB 導入創建，因此無論保存什麼都會重新打開；XZZPH8ZX、畫布大小和 PSB 導入創建，因此無論保存什麼都會重新打開；XZZPHZZXZ、ZZ）讓結構和解壓後的大小；驗證 CRC 和內容雜湊；拒絕不受支援的版本；和屬性測試隨機捆綁/清單。

## 審查清單

對於每個攻擊者控制的計數、偏移、尺寸或長度：

1. 解析成可以表示文件欄位而不被截斷的型別。
2. 在分配之前驗證語意限制。
3. 使用`checked_add`、`checked_mul`或刻意安全的飽和比較。
4. 在切片之前驗證範圍是否位於輸入內部。
5. 根據預算對解碼位元組、物件和遞歸進行收費。
6. 傳回特定於格式的錯誤；永遠不要恐慌或無限循環。
7. 測試零、最大值、最大值加一、截斷和不一致聲明。

## 未來強化

- 定義在嵌套 PSD 資源和嵌入物件之間共享的聚合解析預算；
- 為高度碎片化但大小有限的檔案添加時間/工作計數器；
- 練習 ActionDescriptors 以外的堆疊深度，包括遞迴文件關係；
- 新增特定格式的解壓縮比率和物件計數回歸案例；
- 對受限機器上接受的最壞情況輸入進行基準測試；
- 使用非敏感出處註解保留最小化的模糊偽影。
