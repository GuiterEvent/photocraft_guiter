# 相依性關係

貨物相依性透過`Cargo.lock`固定，並由正常工作區建置、測試、clippy 和WebAssembly作業執行。解析器和 GPU 相依性值得額外審查，因為它們處理攻擊者控制的資料或與本機驅動程式互動。

## 目前儲存庫狀態

目前樹中不存在`cargo-deny`策略檔案、`cargo-audit`作業或等效的相依性建議工作流程。在設定和 CI 證據落地之前，不要描述已實施的相依性審計。

## 建議檢查

```sh
cargo audit
cargo deny check
```

未來的`deny.toml`應由維護人員審查，並對接受的許可證、諮詢策略、來源規則和重複版本策略進行編碼。諮詢例外需要所有者、理由、補償控制和到期/審查日期。 CI 工具和 GitHub Actions 也應該作為相依性進行版本固定和審查。

相依性變更應記錄為什麼需要 crate、它是否處理不受信任的輸入、不安全/本機程式碼暴露、支援的目標、維護狀態和許可證相容性。避免用掃描結果取代來源審查。
