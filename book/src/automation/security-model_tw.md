# 自動化安全模型

自動化請求是不受信任的輸入，其潛在影響超出了活動文件。開啟、儲存、渲染到路徑、首選項變更、應用程式控制、指標/類型注入和任意引擎命令具有不同的風險級別，但目前共享廣泛的傳輸存取權限。

|控制|現狀 |
|---|---|
|僅環回 TCP 綁定 | **實作**用於桌面控制和無頭 TCP 服務 |
|工作室運輸| **針對 MCP 和無頭 JSON 行實作** |
|命令級錯誤處理 | **已實施**，具有特定於命令的測試和`panic_hunt`覆蓋範圍 |
|控制色版認證 | **已實作：** TCP 方法調度之前需要 256 位元不記名令牌 |
| MCP 能力範圍 | **部分：** 僅具有檔案系統讀取/寫入功能；缺少通用工具範圍 |
|允許讀取/寫入根 | **實作：**單獨的啟動時根，缺少權限失敗關閉 |
|符號連結安全功能檔案系統 | **實作：**相對操作使用保留的目錄功能並拒絕連結轉義 |
|請求位元組和 JSON 深度限制 | **部分：** TCP 和無頭 JSON 行 stdio 上的 1 MiB 請求行限制（MCP stdio 輸入沒有位元組上限）；沒有明確的 JSON 深度策略 |
|批量步數限制| **實施：** 無頭和 MCP 批次的 256 個步驟 |
|回覆大小限制 | **實作：** 8 MiB 編碼的 JSON/MCP 結果；批次回覆預算摘要|
|無頭預覽預算| **實現：** 2048 像素請求邊緣，67,108,864 來源像素，5 MiB 編碼 PNG |
|連線/工作人員限制 | **實作：** 16 個活動 TCP 連線；每個接受的活動連線一個工作執行緒 |
|安全審計事件| **提議** |

## 網關狀態與剩餘工作

```text
MCP or control client
          |
 authenticated session
          v
 security gateway
   - general method capabilities (proposed)
   - path handles/read-write roots (implemented)
   - request budgets
   - command policy
   - audit events
          |
          v
 command engine / UI shell
```

目前的令牌證明擁有秘密，但不提供通用方法授權。
實施檔案系統句柄和防禦性命令路徑策略；明確非檔案系統
功能、會話記憶體/命令持續時間預算和審計事件仍然存在。預覽和
回覆上限不綁定所有文件操作或桌面截圖擷取。私有代幣處理、流程
隔離和最低特權執行仍然是實際的遏制措施。
